# agv-gui — GUI для AdGuard VPN CLI (C++ / Qt6 / QML)

Перенесено из чата claude.ai «AdGuard VPN: исключение приложений» (2026-10-25).

## Исходная задача

AdGuard VPN CLI для Linux умеет исключения только по доменам/IP, по приложениям — нет
(есть на Windows/macOS/Android). Цель: GUI-клиент с исключением приложений «галочкой, как на винде».

Окружение автора: TUN-режим, `tun0` (172.16.219.2), Wi-Fi `wlp2s0`, шлюз 192.168.0.1, uid 1000,
Hyprland. Мотивирующий кейс: Genshin Impact через Wine/Lutris (UDP :22102 к 8.211.x.x, IP меняются).

## Требования

- Логика на C++, **без Python**.
- UI: Qt6 + QML, без тяжёлых сторонних библиотек (лёгкие/средние — можно).
- Адаптивная вёрстка: Hyprland (полный экран, половина, четверть), KDE и др.
- Работает на всех популярных дистрибутивах.
- Красиво и современно, без перебора. Цвета как в оригинальном AdGuard VPN.
- В приложении только полные команды `adguardvpn-cli ...` (agvc, agvEa, agvEs, agvs — личные алиасы автора).

## Механизм исключения приложений

cgroup v2 → nftables `socket cgroupv2` → `meta mark` → `ip rule fwmark` → отдельная таблица (421)
с default через физический интерфейс.

- `adguardvpn-cli config set-tun-routing-mode SCRIPT` + `create-route-script`: AdGuard не ставит
  маршруты сам, а вызывает скрипт с именем TUN в `$1`. Скрипт обязан поставить маршруты VPN
  (как дефолтный: `0.0.0.0/1`, `128.0.0.0/1`, `2000::/3` через tun), затем наши правила.
  Всё идемпотентно.
  - Исключать IP VPN-сервера не нужно: AdGuard привязывает свои upstream-сокеты к физ. интерфейсу
    (`SO_BINDTODEVICE`, в `ss` видно `192.168.0.11%wlp2s0`), петли нет. Дефолтный скрипт тоже без
    исключения. Правило-страховку на IP сервера можно оставить опционально.
  - Скрипт вызывается только на подъём. Хука на опускание нет: маршруты `dev tun0` исчезают с
    интерфейсом сами, а наши `ip rule` / таблица / nft — нет → демон ловит удаление tun через
    rtnetlink и чистит сам.
  - Проверить, что `site-exclusions` в SCRIPT-режиме работают как в AUTO.
- `type route hook output` chain: смена метки → перемаршрутизация.
- `masquerade` на физ. интерфейсе для помеченного трафика (source может быть уже 172.16.219.2).
- `rp_filter=2` и для `all`, и для физ. интерфейса (эффективное значение = max(all, iface)).
- Зеркальные правила для IPv6.
- Приоритет нашего `ip rule` должен быть раньше правил VPN.
- nft привязывает путь cgroup к inode при загрузке правила → cgroup должен существовать постоянно.
  При рестарте демона cgroup пересоздаётся с новым inode → демон при старте всегда перезагружает
  свою nft-таблицу и заново переносит процессы из списка исключений.
- cgroup сокета фиксируется при создании сокета: перенос уже работающего процесса влияет только на
  новые соединения → в GUI показывать «перезапустите приложение».
- Wine: `/proc/<pid>/exe` = wine64-preloader → матчить по cmdline / родителю; потомки наследуют cgroup.
- DNS исключённого приложения идёт через systemd-resolved → через VPN (обычно ок).
- Смена интерфейса/шлюза (Wi-Fi ↔ Ethernet) → rtnetlink, перестроить таблицу.

Захват процессов:
1. При запуске: `agv-run <cmd>`; переписанные копии `.desktop` в `~/.local/share/applications/`
   с `Exec=agv-run ...`. `agv-run` подключается к unix-сокету демона, демон узнаёт PID через
   `SO_PEERPIDFD` (ядро ≥ 6.5, без гонки переиспользования PID; иначе фолбэк на `SO_PEERCRED`),
   переносит процесс в свой cgroup, после чего `agv-run` делает `exec`. Только libc, без D-Bus.
   Ветку `systemd-run --user --slice=...` не используем: cgroup исключений один — у демона.
2. Уже запущенные: netlink proc connector (`PROC_EVENT_EXEC`) → матч по exe/cmdline/родителю →
   запись PID в `cgroup.procs`.

Риск: перенос процесса из `user@1000.service/app-*.scope` в cgroup системного сервиса.
Порталы (`xdg-desktop-portal`) и некоторые DE опознают приложение по имени scope; процесс не
убивается при logout; учёт ресурсов уходит в другую ветку. Для игр некритично, для браузеров
(screen sharing) — проверить на этапе 5. Запасной вариант: BPF-программа `cgroup/sock_create`,
которая ставит метку сокету без переноса процесса.

## Компоненты

| Компонент | Что делает | Зависимости |
|---|---|---|
| `agvd` — демон (root, systemd service) | вызывает adguardvpn-cli, маршруты, nftables, cgroup, exec watcher, D-Bus API | Qt6 Core + DBus |
| `agv-gui` — интерфейс (user) | окно и трей, общается только с демоном | Qt6 Quick, QuickControls2, DBus, Widgets (только трей) |
| `agv-run` — лаунчер | запускает процесс сразу в cgroup исключений | только libc |
| `org.agv.Daemon.xml` | D-Bus интерфейс, общий для демона и GUI | — |

- Polkit: прямой D-Bus вызов `CheckAuthorization`, без polkit-qt.
- netlink (proc connector, rtnetlink) — сырые сокеты.
- nftables — через `nft -j -f -`, не линкуем libnftables.
- cgroup: `Delegate=yes` в unit демона → `agvd.service/novpn/app-<id>`; без systemd — `/sys/fs/cgroup/agv/`.
- Свой sub-cgroup + nft `counter` на приложение → потрафиковая статистика.

## CLI

Команды: `connect -l <loc>`, `disconnect`, `status`, `list-locations`,
`site-exclusions add/remove/show`, `config show/set-*`. Точный синтаксис — по `adguardvpn-cli --help-all`.
`CliAdapter`: снимает ANSI, парсит текст в структуры, тесты на сохранённых образцах вывода.
Если есть машиночитаемый вывод — использовать его.

Полезные опции config: `set-exclusions-tcp-early-ack`, `set-exclusions-preresolve`,
`set-bound-if-override`, `set-tun-device-name`.

## Результаты разведки (этап 1, CLI v1.8.1, 2026-10-25)

Образцы вывода: `tests/fixtures/cli/1.8.1/`.

- **Машиночитаемого вывода нет** (ни `--json`, ни аналогов) → парсим текст.
- ANSI-коды (`\e[1m` … `\e[0m`) есть **даже при выводе не в TTY** → `CliAdapter` всегда их снимает.
- Форматы:
  - `status`: свободный текст. «VPN is disconnected» / «Connected to ATHENS in TUN mode, running on
    tun0» + строка-подсказка. Из connected извлекаем локацию, режим и имя TUN. (Образец connected
    скопирован из терминала — ANSI-коды в нём, вероятно, потеряны.)
  - `config show`: `\tKey: Value`, значения вида `Default (on)` → различать «по умолчанию» и явное.
  - `list-locations [count]`: таблица с фиксированными колонками `ISO COUNTRY CITY PING ESTIMATE`,
    затем пустая строка и подсказка. Города могут содержать пробелы → резать по позициям заголовка.
  - `site-exclusions mode` / `show`: «Current exclusion mode is GENERAL», «Exclusions for GENERAL mode:»
    + по домену на строку (поддерживаются маски `*.ru`).
  - `license`: email, тариф, число устройств, дата окончания.
  - Ошибка/неверная подкоманда: «A subcommand is required» + help → признак ошибки парсинга.
- `connect` полезные флаги: `-f/--fastest`, `-y/--yes` (без интерактивных вопросов — обязательно
  для демона), `-4/-6`, `--no-fork`, `--pid-file`, `--boot` (бесконечные ретраи).
  Недокументированный `--wait-for-parent` встречается в реальном запуске.
- `config create-route-script` при существующем скрипте не перезаписывает его, но
  **печатает «Config has been updated»** — команда не read-only, вызывать осознанно.
  Скрипт: `~/.local/share/adguardvpn-cli/setup_routes.sh`, владелец root, `0700`.
  Дефолтное содержимое (`tests/fixtures/cli/1.8.1/setup_routes.default.sh`): три `ip route add`
  в main-таблицу через `$1`, без `ip rule`, без исключения приватных сетей (LAN работает за счёт
  более специфичного connected-маршрута; 10/8 и прочие уйдут в туннель — отличие от AUTO).
  Правила AUTO `30800 sport 1-1024 / 5900-5920 → main` в SCRIPT-режиме тоже пропадают.
- Каталог данных: `~/.local/share/adguardvpn-cli` (конфиг, `vpn.socket` от root, логи).

### Как AUTO-режим ставит маршруты (снято при поднятом VPN)

- `ip rule`: `30800 sport 1-1024 lookup main`, `30800 sport 5900-5920 lookup main`,
  `30801 lookup 880`. Наше правило с приоритетом 100 гарантированно раньше.
- Таблица 880 (v4): 61 маршрут `dev tun0` — дополнение до приватных сетей (10/8, 172.16/12,
  192.168/16, 127/8, 169.254/16, multicast) **с дыркой под IP VPN-сервера** (сейчас 104.164.217.75,
  к нему идут TCP:443 через wlp2s0). Это и есть то, что скрипт в SCRIPT-режиме обязан воспроизвести.
- Таблица 880 (v6): `2000::/4`, `3000::/4` через tun0. tun0: `172.16.219.2/32`, `fd01::2/128`.

- Коды выхода: ошибка использования (`adguardvpn-cli` без подкоманды) → **106**; `config` без
  подкоманды печатает help с кодом 0. Демон смотрит сначала на код выхода, потом на текст.
- `list-locations` (полный список, 80 локаций): колонки фиксированной ширины (ISO 6, COUNTRY 21,
  CITY 31), переполнений нет, все пинги числовые. Есть города вида «Moscow (Virtual)».

### Решения

- **Состояние CLI привязано к каталогу данных (`$HOME`).** От пользователя `status` → «disconnected»,
  `sudo status` → «Connected to ATHENS»: работающий процесс от root живёт в каталоге root, и
  `config show` от пользователя может показывать не тот конфиг, что активен.
  → Демон всегда запускает CLI с `HOME=/var/lib/agvd` (systemd `StateDirectory=agvd`). Не зависит от
  пользователя, работает для всех. В GUI — «Импортировать вход из `~/.local/share/adguardvpn-cli`»
  (копирование каталога данных с правами root).
- Если найден чужой запущенный `adguardvpn-cli connect` (другой `HOME`), демон не запускает второй
  экземпляр, а показывает в GUI: «VPN запущен вне agv-gui» с кнопкой «Перехватить» (disconnect
  чужого + connect своего).
- D-Bus: `dbus/org.agv.Daemon1.xml`, адаптор генерируется `qt_add_dbus_adaptor`. Имя шины
  переименовать в принадлежащее проекту пространство имён до первого релиза.
- **Вход — device code.** `adguardvpn-cli login` печатает ссылку и ждёт подтверждения в браузере,
  TTY не нужен. Демон отдаёт ссылку сигналом `LoginUrl`, GUI открывает браузер; ссылка живёт ~30 мин.
- Коды выхода: **11** — не выполнен вход (status, license, list-locations), **106** — ошибка вызова.
  Исключения сайтов работают и без входа.
- **polkit**: `org.agv.daemon.control` (подключение, исключения, лицензия) — активному пользователю
  без пароля, как в NetworkManager; `org.agv.daemon.configure` (настройки, вход/выход) —
  `auth_admin_keep`. Чтение — без проверки.
- **`KillMode=process`** в unit: VPN-процесс (форк CLI) и исключённые приложения живут в cgroup
  демона и не должны умирать при рестарте/обновлении `agvd`.
- `setConfig` принимает только белый список ключей и значений; `tun-routing-mode` и
  `tun-device-name` принадлежат движку маршрутизации и снаружи недоступны. Свободные значения не могут
  начинаться с `-` (не примет за опцию).
- Демон передаёт в polkit флаг вызывающего `ALLOW_INTERACTIVE_AUTHORIZATION`; без него при нужном
  пароле отвечает `org.freedesktop.DBus.Error.InteractiveAuthorizationRequired`. GUI ставит
  `QDBusMessage::setInteractiveAuthorizationAllowed(true)` на вызовы, где ждёт окно пароля.
- CLI запускается с пустым окружением (только `HOME`, `PATH`, `LANG`, `TERM=dumb`, `NO_COLOR`),
  команды — строго по одной.

### Открытые вопросы

- Образцы `status` в состоянии connecting, вывод `connect` и `disconnect`.

## Движок исключений, итог (этап 3)

Заменяет SCRIPT-режим и таблицу 421 из исходного плана.

- **AdGuard остаётся в AUTO.** Его туннельные маршруты живут в таблице 880 (`ip rule 30801`), а `main`
  не трогается: там default через физический интерфейс, его ведёт NetworkManager. Поэтому
  исключённому трафику хватает `ip rule fwmark 0x61677664 lookup main priority 30700` (раньше
  правил AdGuard 30800/30801; AdGuard сам обходит VPN так же — `sport 1-1024 lookup main`).
  Не нужны ни route script, ни своя таблица, ни слежение за шлюзом.
- nftables, таблица `inet agvd`, загружается целиком атомарно (`table; delete table; table {…}`):
  - `output` (route hook): `socket cgroupv2 level N "<own>/novpn/<id>" counter meta mark set … ct mark set meta mark`;
  - `input`: те же совпадения со счётчиком — входящий трафик приложения;
  - `prerouting`: `ct mark … meta mark set ct mark` — ответы несут метку;
  - `postrouting`: `meta mark … oifname != "lo" masquerade` — источник уже выбран под туннель.
- `net.ipv4.conf.all.src_valid_mark=1` (как wg-quick): reverse-path фильтр учитывает метку ответа,
  `rp_filter` глобально не ослабляем. Исходное значение хранится в `routing-state` и
  восстанавливается `agvd --cleanup`.
- cgroup: `<cgroup демона>/novpn/<app-id>` (`Delegate=yes`), плюс встроенная группа `run` для
  `agv-run cmd` без настроенного приложения. Пути резолвятся nftables при загрузке → каталоги
  создаются до загрузки правил. Удалённое/выключенное приложение: процессы возвращаются в cgroup
  демона (новые соединения снова через VPN), каталог удаляется.
- Правила действуют всегда, пока демон работает (без процессов в группах они ничего не меняют) и
  переживают его рестарт вместе с процессами (`KillMode=process`); снимаются только
  `agvd --cleanup` (его вызывает `dev-install.sh --uninstall`). `routing-state` хранит пути cgroup,
  потому что `--cleanup` запускается вне cgroup сервиса.
- `agv-run`: `/run/agvd/run.sock` (`RuntimeDirectory=agvd`), запрос `RUN [id]\n`, ответ `OK` /
  `ERR …`; демон берёт pid из `SO_PEERPIDFD` (иначе `SO_PEERCRED`), так что клиент переносит только
  себя; любой локальный пользователь может исключить свои процессы. Если демон отказал или
  недоступен — команда не запускается (никакого тихого запуска через VPN).
- DNS исключённых приложений по-прежнему идёт через DNS-прокси AdGuard (если `Change system DNS: on`).

## Интерфейс

- Экраны: Главная (подключение, локация, статус, пинг) · Локации (поиск, сортировка по пингу,
  избранное) · Исключения (Сайты / Приложения, режимы General/Selective) · Настройки · Аккаунт.
- Выбор приложений: `.desktop` из `XDG_DATA_DIRS` + flatpak exports.
- Иконки: `QIcon::fromTheme` + image provider.
- Отдельно обрабатываем Wine/Lutris, Steam, AppImage.
- Брейкпоинты: `< 520px` — одна колонка, нижняя навигация; `520–900px` — боковая панель с иконками;
  `> 900px` — панель с подписями + список/детали; компактный режим по высоте.
- `Theme.qml` singleton с токенами поверх стиля Basic (не Material/Universal). Фирменный зелёный
  AdGuard, тёмная/светлая из системы. Точные HEX — со скриншотов официального клиента.
- Анимации 150–200 мс, только переходы состояния и экранов.

## ОЗУ

- Закрытие окна уничтожает `QQmlApplicationEngine`, остаётся трей.
- Экраны через `Loader`/`StackView` по требованию; списки — `QAbstractListModel` на C++.
- Демон без QML.

- **Отрисовка GUI — программная по умолчанию** (`QQuickWindow::setGraphicsApi(Software)`, если не задан
  `QT_QUICK_BACKEND`). Замер (2026-10-25, Hyprland, Mesa): окно открыто — 94 МБ RSS / 22 МБ своей памяти
  против 183 / 41 МБ через GPU; в трее одинаково (59 / 7,5 МБ). Mesa (libLLVM + libgallium, ~70–90 МБ)
  не грузится вовсе; при GPU она остаётся в процессе и после закрытия окна. Визуально без разницы.
  **Если интерфейс разрастётся** (размытие, тени, MultiEffect/ShaderEffect, много полноэкранных
  анимаций, тормоза при растягивании на 4K) — вернуть GPU: убрать эту строку или `QT_QUICK_BACKEND=rhi`.
  Особенности программного рендера при дробном масштабе (Hyprland 1.33, найдено 2026-10-25):
  `layer.enabled` рисуется обрезанным → слои только при GPU (`GraphicsInfo.api`); большой круг из
  `Rectangle { radius: width / 2 }` обрезается справа и снизу → круги рисуем путём (`Circle.qml`).
  Проверять вёрстку снимками с `QT_SCALE_FACTOR=1.3333334`.
